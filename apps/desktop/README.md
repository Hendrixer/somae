# Somae desktop test

Electrobun 2.0.2, an explicit Bun main process, and a system webview. This macOS test uses the Signal/Electric interface and Wave mark. Mobile is deferred. The [execution brief](../../docs/architecture/test-version.md) defines the outcome and evidence; the earlier browser prototypes remain preserved.

## Run

Run `bun install` at the repository root, then `npm run desktop`. The private test service configuration lives in `~/Library/Application Support/Somae/desktop.json`: `api_url` and `desktop_token`. Provision the credential through the deployment's secret workflow; never paste it into code, UI, documentation or reports. Claude Code must be installed and signed in with the person's subscription.

Choose a project folder to start a managed Claude session, or use More → Connections → Connect Claude in my terminal. That installs a user-scoped Somae MCP server and `~/.local/bin/somae-claude` without replacing unrelated configuration. Start that command in a project; resume an exact session with `somae-claude --resume <session-id>`. Custom development Channels require their per-launch Claude notice. An unconfigured running Claude process must restart/resume; this is not arbitrary process attachment.

Connections shows live terminal sessions and running Somae sessions first. Disconnected sessions are kept in a collapsed section, including existing entries from earlier terminal launches; expanding it never starts Claude. Their messages, files, exact session identity and resume behavior remain intact. Presence comes from fresh local heartbeats after each app launch. A graceful bridge shutdown clears it immediately; an interrupted connection expires after 12 seconds. Multiple live Claude sessions in one project stay separate. A new-message draft keeps the session selected from its Message button; if that session disconnects, reopen Connections to choose a destination deliberately rather than silently switching the draft to another session.

Managed sessions use an app-owned interactive PTY. Hiding Somae keeps them alive; quitting stops only the processes Somae started. Reconnect resumes the same session and project. Connections → Open Claude exposes Claude's own terminal screen and explicit setup/permission keys when needed. This is a direct local fallback, not a synthesized permission signal or automatic approval.

## Experience

- Cmd Shift Space summons/collapses the companion. Escape, Cmd W and Get back to it also collapse it to a small floating Wave beacon with the waiting-signal count and shortcut. The beacon appears near the top of the current display without stealing focus; click it to reopen. Reopening Somae from the Dock or choosing Show Somae in the menu bar brings the main window back. A new signal gives Wave four brief wrist-led waves, then it settles even if you leave Somae closed; reduced motion uses a quiet opacity cue. Startup history, polling, revised signals, setting aside and restoring a signal never replay that greeting. The menu-bar count updates while it is hidden. Cmd N starts a message. Left/right navigate signals, Cmd Left sets one aside, numbers or up/down/Enter answer choices, and Enter clears an optional result or dismisses the all-clear state. Required questions need a deliberate response.
- Cmd comma opens a separate Settings window, also available from More and the application/menu-bar menus. Its native close button, Escape and Cmd W close Settings without quitting Somae or discarding the main view. Appearance selects Electric, Infrared or After hours; General controls the floating beacon, desktop notifications and reduced motion. Native notifications are off by default; enabling them asks macOS for permission. New signals can produce silent banners while the companion is closed; clicking one opens its signal. The open companion suppresses banners. Permission denied in macOS stays visible in Settings, and existing preferences never trigger a permission prompt at startup. Preferences persist on this Mac and update already-open windows together.
- Review opens a larger document/image canvas. Click an image to place a numbered note, drag to draw a region, or comment on the whole image. Every new drag works directly, including over saved regions. The canvas keeps compact numbered neutral pins; only the selected or unfinished comment shows its region. The single plus control in the Comments header adds an image-wide comment; there is no duplicate overall-note field. Existing review-wide notes from earlier drafts remain editable in a disclosure. Clicks on saved pins locate their notes; reduced motion preserves their placement during presses. Escape cancels a drag, and a canceled or thin drag never becomes a point pin. Finish or discard an unfinished comment on the same asset before placing another. In documents, select text for a comment or suggested replacement. Compose beside the work in an auto-growing field with no resize handle, repeated heading or asset label. The rail shows comments for the current asset; tab counts locate feedback on other assets. Comment separators span the full rail width, with padding inside each row. Matching pins and comment rows locate each other. Switching assets or versions closes the composer and parks its exact draft; Resume draft reopens it deliberately. Each asset can keep an unfinished comment without blocking another asset. Leaving review also closes the editor without losing its text. The comment rail scrolls independently of its response dock. Enter saves a comment locally with a neutral Save comment control, Shift Enter adds a line, and Escape collapses an unfinished note without discarding it. Notes can be edited or removed before sending. All nonempty open and parked comments are validated and collected into the outgoing batch; any invalid, conflicting or stale unfinished edit stays protected and blocks submission. Saved-comment removals stay disabled while a parked edit depends on its exact original index. Earlier versions are read-only; choose the latest to add feedback. Stale drafts stay intact; discard/restart is an explicit action.
- The source signal determines the response controls. `ask_question` keeps its exact agent-authored choices or free-text answer, with optional artifact comments sent by Send answer. It never gains Approve/Request changes buttons or an approval stamp, even when its text asks about approval. `request_review` binds an exact set of versions and offers only Approve and Request changes; either sends the decision and optional comments back to the agent. Comments add context to the chosen answer or decision without changing its meaning. Long request text is disclosed, while the required response stays directly available. Cmd Enter sends the question answer or approves a review; Cmd Shift Enter requests changes only for a review (inside an open annotation, Enter/Cmd Enter saves that note first). The exact response, comments and one delivery commit atomically, so the answered signal does not remain in Inbox. The Signal and artifact canvas share the same source-bound answer draft. Answering from Signal includes collected comments for that exact question; an unrelated request draft stays untouched. An unconfirmed send freezes its original answer and comments until the same idempotent operation is retried. There is no automatic conversion between question and review types. Unrelated execution or publishing approvals cannot be answered as a content review.
- The library keeps immutable originals and versions, review links, comparison, decision history and exact approved-version pins. Question answers leave approval pins and decision sequences unchanged. A new draft does not replace an approved copy. Requesting changes to an approved version removes its current approved pin while keeping the earlier decision as history; requesting changes to a later version preserves the approved earlier copy. After a response is accepted, Somae advances to the next signal or All caught up. A failed send preserves the draft and its exact idempotent operation, including request revisions and any decision sequences, so a retry cannot send duplicates. History is a single secondary link. Original PDF files can be downloaded; annotatable previews currently cover Markdown, text, inert HTML and images.
- Message/reply drafts and review drafts persist on this Mac. Offline mode displays a cached library and saves drafts; it does not pretend a send succeeded. Integration receipt, explicit Claude acceptance and returned results are separate states.

The real app follows the Signal direction and canonical Somae Design v0.2 tokens: neutral near-black panel chrome, matte control wells, clear body/display hierarchy and the Wave mark. Electric, Infrared and After hours change the accent, while panel/surface/hover colors stay neutral. Brand color is reserved for the mark, the primary decision and small attention indicators; focus, selected comments, pins, region outlines and local Save use neutral semantic roles. `src/view/app.css` owns the app adaptation; edit canonical `packages/design-system/tokens.json` only when changing the shared design language. The downloaded token reference matches that canonical source. Signal actions place the primary action to the right of secondary actions, with queue navigation, Details and Set aside in a separate footer. The all-clear view is one compact aligned block: a small check, “All caught up.” and the primary Get back to it action followed by New message. It omits explanatory copy, successful-delivery receipts and the repeated summon hint. Only pending or unconfirmed delivery gets a concise disclosure. Set-aside signals offer Return to inbox; an empty set-aside view offers Back to inbox, also activated by Enter. Menus and destination/version pickers use keyboard-accessible styled popovers; Escape closes the top layer first. Signal bodies render Markdown paragraphs, lists, emphasis, headings, quotes, code and tables while retaining the separate short-first-line display title. Raw HTML and remote images stay inert; HTTP/S links open through the authenticated host in the default browser, never navigate the companion. The existing Claude tools accept Markdown in their text argument, including legacy text blocks; no API migration is required. In Inbox the original question and a short request excerpt remain visible; expanding the excerpt reveals the full request.

Navigation and new content use the token easing and 210ms entrance; summon uses 350ms. The companion measures content at its destination width, then AppKit interpolates its frame using the canonical 330ms resize duration and easing. Duplicate destinations do not restart the animation, and an interrupted transition continues from the current frame. Browser resize observation pauses during native motion; content mutations can still request a new destination. Incoming navigation content appears when measurement is acknowledged, alongside the window transition. The detached review probe removes viewport-height and flex-fill constraints before measuring intrinsic content, so the resulting destination is independent of the current window height. Image fit uses a stable display-based height limit so resizing cannot keep changing its own measurement. Empty/short views stay compact; review and library use a larger canvas, with scrolling reserved for content that exceeds the display. Background polling keeps the reading surface still and preserves open controls, editing focus and drafts. Menus, presses and receipts have short state transitions. System Reduce Motion and the local reduced-motion preference disable spatial window/view/control animations.

## Boundaries and checks

`src/main/host.ts` owns cloud credentials, local sessions, files, draft/preference writes and the narrow localhost API. The authenticated local state also reports main-window geometry, motion cadence/destination and main, beacon and Settings visibility for native verification. Motion destinations use AppKit's bottom-left coordinates; Electrobun's frame projection uses top-left coordinates. Each owned view receives a fresh one-use boot ticket for its exact path, creating an HttpOnly same-site session cookie; mutations check the exact origin and body bounds. Local preferences contain only theme, beacon visibility, reduced motion and notification enablement, with validated values and private atomic file writes. `src/view` receives explicit client projections, never cloud credentials or raw domain snapshots. Agent HTML is an inert text model; images use a sandboxed originals route. No agent content gets privileged RPC or navigates the application.

`npm run check:desktop` runs Bun host/channel integration tests, TypeScript checks and the actual native build. On a fresh clone, run `npm run setup:desktop` first: `tsconfig.json` extends `.hutch/devkit/tsconfig.json`, and the `electrobun/*` imports resolve from that projected devkit, not from npm. CI runs the same step before `npm run verify`. `npm run verify` includes these plus Worker/SQLite/R2, domain, source/context and token checks. Builds copy generated canonical tokens/Wave into ignored outputs and bundle the channel. Do not edit `.hutch/`, `dist/` or `build/`. Quit the dev app before rebuilding so its Hutch lease is released.

The summon shortcut uses the small `src/native/shortcut.m` bridge and Carbon hotkey registration. Electrobun 2.0.2's key monitor requires Accessibility access and misses the app's own events; this bridge reserves only the summon chord without that permission. Registration reports real conflicts. Bun consumes queued presses on its own thread and releases the reservation on quit. The build needs Apple Command Line Tools (or configured Xcode); `scripts/native.ts` compiles and bundles the bridge. The desktop tests check cross-process conflicts and release/re-registration using macOS itself; stop Somae before running them. `src/main/beacon.test.ts` also compiles/runs `src/native/beacon.test.m`, checking centered/clamped frames and compact restoration, actual intermediate AppKit resize frames, duplicate suppression, interruption and reduced-motion cancellation. The same harness loads the real review CSS, layout module and image geometry at several viewport heights to catch self-sizing feedback, confirms real content still grows the window, preserves the live question radio selection and compact control geometry during hidden measurement, and checks that a moved expanded canvas retains its center during later resizing. Its transparent ordered WKWebView window never activates or sends OS input. `src/main/notifications.test.ts` checks startup baseline, signal identity deduplication, offline recovery and explicit origin-guarded notification enablement; unbundled test processes cannot request macOS permission or post a banner. `src/view/beacon.test.ts` checks the finite wave, idle polling and reduced motion. `src/view/signal-content.test.js` checks Markdown structure, title compatibility and inert unsafe content; host tests check authenticated HTTP/S opening. `src/view/annotation-drafts.test.js` checks parked exact-version drafts, conflict preservation and all-or-nothing preparation of feedback. `src/view/review-context.test.js` checks exact review request descriptors, explicit legacy answers, unsupported execution approvals and artifact sets. `src/view/image-gesture.test.js` checks repeated/overlapping regions, click-versus-drag thresholds, captured/clamped geometry and pointer ownership. The same native harness checks stable class identities, overlay hit areas, first-click policy, tracking, atomic click/hover delivery and accessibility. Native keypress, actual mouse QA and visible motion review remain separate; cadence metrics alone do not prove perceived smoothness.

The same bridge clips the actual transparent AppKit content surface to the canonical `radius.panel` token and restores its native shadow. `src/main/window.ts` consumes the public Electrobun window pointer only in the main process; the UI never receives it. The main window starts hidden until its material is configured, has a 480 × 260 minimum and uses the custom header's drag region. Measured compact content is at most 680 points wide; review/library can grow to 1180. Both dimensions are capped by the current display's usable frame. Review and library frames center when entering the expanded canvas, then preserve the current canvas center during content resizing so a manually dragged position remains yours. Returning to the compact companion restores its prior header position when that position fits the screen. Initial/hidden sizing is immediate; subsequent visible changes use `NSAnimationContext` with non-forced drawing. Bun observes an atomic completion flag and never steps intermediate geometry or queues a main-thread read for every animation frame. Showing it emits `somae:summon` for the view's presentation; hiding is immediate and preserves the draft.

Settings uses a retained 760 × 600 native window with an inset traffic-light close control. Closing hides and reuses it, returning keyboard focus to the visible companion; the active Settings window receives Cmd W before the main companion does. Cmd H hides both Settings and the companion. The 268 × 48 beacon is a separate rounded floating surface, shown without activation on the display under the pointer. A transparent native button over its action area accepts the inactive first click; the 21-point drag grip remains uncovered. HTML still supplies the material and accessible action. Native click/hover state crosses to Bun through an atomic queue polled only while the beacon is visible; no WebKit classes are replaced or patched. Collapsing the companion relinquishes application focus when Settings is also closed. Hiding or collapsing the main window keeps local sessions alive; only Quit stops Somae-owned Claude processes. System menu shortcuts and the custom-view fallbacks use the same local shell endpoints.

Build success is not a product check. Inspect native and desktop/narrow browser views, focus/drafts/advance/all-clear, actual Claude review/revision, and reopen/recovery. Local tests do not log in or spend subscription usage. The separate live checks do; their redacted evidence belongs in ignored `artifacts/verification/`.

The feedback interaction borrows direct placement and linked pins from [MarkUp.io’s comment workflow](https://educate.ceros.com/en/articles/12454641-leaving-feedback-on-a-markup) and [canvas/sidebar selection](https://educate.ceros.com/en/articles/12454599-actioning-feedback-on-a-markup). Somae keeps its own batch boundary: Save comment only saves a local draft; Send answer includes the original question response and optional feedback, while Approve or Request changes includes the content-review decision and optional feedback. Point pins use tiny normalized region anchors under the existing contract. Draft annotation composition captures the exact item/version/anchor and survives navigation or hiding; an arriving revision never retargets it.

The optional native alert adapter uses Apple's UserNotifications framework, keeping OS callbacks in a small Objective-C delegate and passing activation IDs to Bun through a bounded queue. The first successful library sync establishes the arrival baseline; subsequent new active signal identities produce attention once per app run. A signal revision or a count change alone does not. Notifications are local to this running app; they do not deliver after Somae quits. The bridge reads existing permission at startup and requests it only from the Settings toggle. macOS Focus, alert style and system permission still govern presentation. Build and protocol checks do not establish a real permission grant, visible banner or click receipt on a person's Mac.
