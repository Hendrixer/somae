## Run and verify

Install with `bun install` at the repo root. `bun run dev` here serves a local Worker on port 4781. Set fresh `SOMAE_DESKTOP_TOKEN` and `SOMAE_BRIDGE_TOKEN` in ignored `.dev.vars`; keep credentials out of code and reports. `bun run types` regenerates binding/runtime types. `npm run check:api` runs real Worker/SQLite/R2 integration tests, TypeScript checks and a deployment dry run. `npm run verify` also checks the native build.

Routes are `/health`, person-only `/v1/library`, role-allowlisted `/v1/operations`, endpoint-scoped `/v1/inbox`, bounded `/v1/artifacts`, and authorized `/v1/originals/:digest`. Original downloads use attachment/sandbox headers. Endpoint operation `agent.review` publishes an explicit content review request pinned to exact document/image versions. A person's `review.submit` can answer that request, include every feedback note and record the version decisions in the same atomic response/message/outbox transition. Content review does not authorize execution or external publication.

Questions remain a separate interaction. `agent.question` offers exact choices or a free-text answer; a person's `review.submit` can carry that exact `source_request.value` and optional artifact feedback without a `decision` or `expected_sequences`. An answer with no comments is valid. The response, any version-pinned feedback and one outbox delivery commit together, without writing approval pins or decision history. Question wording and option labels never convert it into a content review. Only `agent.review` supplies the fixed Approve / Request changes actions.

Response deliveries include the exact offered question, signal revision, response value and selected choice/action label. Approval responses also include the pinned terms digest. The envelope retains the complete original human message, including the review ID, exact artifact versions, notes and suggested replacements; the receiving agent does not infer option numbering or lose feedback behind a response value. Forwarding is distinct from integration receipt and explicit agent acceptance. The desktop channel journals handoffs locally and stops reinjection after an uncertain restart. Its separate Bun transport tests exercise that policy.

The desktop refuses a content decision or legacy version approval while decision support is absent, and refuses a question answer with artifact feedback while question-feedback support is absent. Both return `service_updating`, preserve local drafts and make no operation POST to a service that could ignore the new semantics. Live evidence and final native QA remain separate from this gate.
