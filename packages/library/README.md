# Review and library boundary

Application-level review state extends the existing communication kernel without introducing tasks. `index.js` builds a synchronous candidate transition: communication commands run through `packages/domain`, and review metadata, approval history, drafts and immutable artifact references are returned with that same candidate. The host must persist the entire returned state atomically before replying. Rejected operations leave the caller's state unchanged.

This package does not store bytes or authenticate requests. The Worker supplies a trusted principal separately from payloads, stores original bytes by verified digest in R2, and commits the entire candidate inside SQLite-backed Durable Object transactions. Its client projection excludes session/workspace routing and internal idempotency/audit data. `index.d.ts` describes host records; use the projection in views.

Endpoint-authored terminal conversations use `agent.open`, guarded `message.publish` and exact `conversation.bind` in one candidate. They create no fake human message or delivery. Agent questions expose required native choices or text; person responses atomically answer the signal and enqueue the same-session continuation. `agent.review` publishes a structured content-review request pinning its exact artifact set, with Approve and Request changes actions. Its terms explicitly cover content review only; neither action grants execution or external publishing permission. These application operations reuse the existing kernel commands.

## Review rules

- Review feedback pins exact artifact versions in one conversation. A new version makes an unsubmitted old-version review stale; preserve its draft and ask the person to inspect the current work.
- Text anchors identify a stable block, UTF-16 offsets and the exact quote within the reviewed version. Image anchors use normalized coordinates within the image. Invalid anchors cannot create a message or outbox delivery.
- Suggested replacements are instructions for the agent, not an edit already made. Feedback submits as one immutable review plus one human message and outbound delivery in the shared command boundary. A decision may be `approve` or `reject`, with optional notes; either decision notifies the agent even with no notes.
- Revisions reuse artifact identity with `expected_revision`. An optional `review_id` must refer to feedback for that item and source version. Arrival of a revision does not automatically resolve every comment.
- A decision requires an `expected_sequences` map containing exactly every reviewed artifact ID and its current decision sequence. Decisions are retained in append-only `decision_history` with a current per-artifact `decisions` pointer. Older persisted state falls back to its existing approval sequence. Approval updates the approved-copy pointer; rejection removes an approval of that same version, while retaining an approved older version. New drafts never move these pointers; history is retained.
- A review tied to an offered request includes `source_request` with the exact signal revision and interaction ID. Structured review requests carry the matching canonical approve/reject `value` and terms digest, and require their entire pinned artifact set. The review, response, answered signal, decision records, draft removal and one message/outbox commit together. Failures retain the draft. The presence of an overlapping active structured request prevents sending an independent decision that would leave the original request unanswered.
- Agent questions retain their exact offered choices, or a free-text answer when no choices were offered. A question response from the artifact canvas uses `source_request.value` with no review `decision` or decision sequences; comments are optional, including zero comments. The exact canonical answer, optional artifact feedback, answered signal, draft removal and one message/outbox commit together. Answering a question never changes artifact approval or decision records, even if an option happens to say “approve.” The canvas reserves fixed **Approve** / **Request changes** actions for structured `agent.review` requests. Labels are never interpreted or converted to actions. Execution approvals and unrelated requests cannot be answered through artifact feedback. Without a source request, feedback or an independent artifact decision sends one standalone review message.
- `version.approve` remains a compatibility alias for a one-artifact approval that sends its available draft feedback and a delivery; incompatible multi-artifact or unfinished annotation drafts are preserved by rejecting the operation. Already cached legacy approvals replay their original result without new notification. Review retries use the original accepted result, recheck current communication authority and never create a second decision or delivery.
- Reading, Done and set-aside remain person-owned queue changes. Done cannot clear a required unanswered interaction.
- Documents become an inert block model: Markdown/HTML text can be read and selected naturally, with scripts, hidden content and URLs excluded from the privileged view. Original bytes are retained separately. PDF originals can be retained before a specialized annotatable PDF viewer exists.

## Verification

Run `node --test packages/library/*.test.js`; real storage/transport checks are in `apps/api/test/worker.test.ts` and run with `npm run check:api`. The contract and ontology connect these policies to ordinary checks. The desktop adds Bun channel/host checks and TypeScript/native builds. Passing tests alone is not proof of live Claude behavior; inspect the separately recorded real-agent evidence.
